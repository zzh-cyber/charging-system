# 用户端 Web 大屏第一版需求矩阵

> **目标**：用户登录 Web 页面后，可以查看自己的充电概览、历史订单、行为画像、充电与消费趋势、智能建议和智能报告。  
> **版本范围**：第一版最小可运行版本（MVP），优先保证真实数据、用户隔离、空数据可用和验收闭环。  
> **编制日期**：2026-09-14  
> **建议架构**：用户 Web → Flask HTTP API → TCP:9000 `charging-server` → MySQL。Flask 只做静态资源、HTTP 参数转换和 TCP 转发，用户身份最终由 C++ 服务端根据 token 解析。  
> **编号范围**：UD-001～UD-055，独立于现有 NO.1～126。
> **分工原则**：组长翟梓涵统一负责范围/口径、API 与 TCP 协议、协议测试及最终代码合并；其余任务由朱雅琪、邓雅心、牛昀轶、马晓钰分担。第一版 UI 只要求功能可用和基本状态完整，暂不细化视觉设计。

## 一、统一业务口径

| 项目 | 第一版约定 |
|---|---|
| 当前用户 | 只能由 `Authorization: Bearer <token>` 对应的会话获得；前端不得传 `user_id` |
| 有效统计订单 | 概览、画像、趋势、建议和报告只统计 `charge_order.status='settled'` |
| 历史订单 | 默认显示当前用户全部状态订单，可通过 `status` 筛选 |
| 累计消费 | 只汇总已结算订单 `amount`，不包含 `pending_payment` |
| 趋势归属时间 | 使用订单 `end_time`；按 Asia/Shanghai 自然日分组 |
| 默认周期 | 大屏趋势、建议和报告默认最近 30 天；趋势允许切换 7 天/30 天 |
| 时段划分 | 早间 06:00–11:59；午后 12:00–17:59；晚间 18:00–23:59；夜间 00:00–05:59 |
| 活跃度 | 近 30 天 0～2 单为低活跃，3～7 单为中活跃，8 单及以上为高活跃 |
| 快慢充偏好 | 快充占比 ≥60% 为 `fast`，≤40% 为 `slow`，其余为 `mixed` |
| 增长率 | 与前一个等长周期比较；上期为 0 时返回 `null` |
| 新用户 | 数值返回 0、列表返回 `[]`、对象按合同返回空值，不得 500 或白屏 |
| 预测缺失 | `load_forecast` 无数据时退化为历史行为建议，不影响其他模块 |
| 时间格式 | HTTP JSON 统一使用 ISO 8601，例如 `2026-09-14T15:30:00+08:00` |
| 金额与电量 | 数据库使用 DECIMAL；接口返回保留两位小数的 JSON number |

## 三、HTTP 与 TCP 映射

| HTTP 接口 | 方法 | TCP type | 主要参数 | 主要响应 |
|---|:---:|---|---|---|
| `/api/user/login` | POST | `login` | body: phone, register | token、用户摘要 |
| `/api/user-dashboard` | GET | `user_dashboard` | period 默认 30d | 首屏主要模块整包 |
| `/api/user/orders` | GET | `user_orders` | page、page_size、status、start_date、end_date、station_id、pile_type | total、items |
| `/api/user/profile` | GET | `user_profile` | 无 | 累计数据、偏好、标签 |
| `/api/user/trends` | GET | `user_trends` | period=7d/30d、granularity=day | 连续趋势、增长率 |
| `/api/user/recommendations` | GET | `user_recommendations` | 无 | 建议列表、生成时间 |
| `/api/user/report` | GET | `user_report` | period=7d/30d/all | 摘要、统计、评分、建议 |

除登录外，HTTP 层从请求头读取 Bearer token，并放入 TCP JSON 顶层：

```json
{
  "type": "user_profile",
  "token": "<UUID>",
  "data": {}
}
```

## 四、推荐规则（第一版固定规则）

| 类型 | 触发条件示例 | 输出要求 |
|---|---|---|
| time | 常用时段为晚间，且常用站最新 1h 预测为高拥堵 | 建议提前或延后充电，并说明历史占比和预测负荷 |
| station | 常用站 `pred_idle=0` 或 congestion=high，其他启用站空闲更多 | 推荐一个替代站，说明预计空闲桩数；第一版不计算导航距离 |
| pile_type | 快充占比高且平均单次电量较小 | 提示短时补电可继续快充；非赶时间可尝试慢充 |
| frequency | 近 30 天充电频次明显集中或间隔过长 | 给出规律充电提示，不涉及电池故障诊断 |
| price | 常用站价格高于启用站平均价格 | 推荐关注低价时段/站点；无分时电价时不得虚构具体低谷价格 |

每个用户最多返回 5 条，按 `priority ASC, generated_at DESC` 排序；同一类型第一版最多一条。

## 五、验收场景

| 场景 | 操作 | 通过标准 |
|---|---|---|
| 正常用户 | 登录演示用户并打开 `/user` | 首屏一次加载出用户、KPI、画像、趋势、建议和报告 |
| 订单筛选 | 切换状态、日期、站点、快慢充并翻页 | 总数和列表一致，所有订单属于当前用户 |
| 趋势切换 | 在 7 天和 30 天间切换 | 日期连续，空白日期补 0，图表和汇总一致 |
| 新用户 | 注册一个没有订单的手机号并登录 | 页面不报错，KPI 为 0，图表为零序列，列表/标签/建议为空 |
| 预测缺失 | 临时使用无 `load_forecast` 记录的环境 | 建议退化为历史规则，其他五个模块正常 |
| 越权 | A token 携带 B 的 user_id 请求全部接口 | 返回内容仍只属于 A，或直接拒绝非法字段 |
| token 失效 | 使用无效/过期 token 刷新页面 | HTTP 401，前端清 token 并回到登录页 |
| 服务异常 | 停止 TCP 服务后刷新 | Flask 返回 504/503，前端显示可重试错误，不白屏 |
